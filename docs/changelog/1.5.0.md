# BeaverDeck 1.5.0

`BeaverDeck 1.5.0` is a configuration portability, Insights, troubleshooting, and security release.

## Highlights

- moved authentication configuration to a portable YAML snapshot stored in a Kubernetes Secret
- added admin-only configuration import and export for local users, roles, Google OAuth, OpenID Connect, and Azure Entra ID
- expanded Node, Workload, GPU, and Security Insights while reducing unnecessary data loading
- improved multi-container logs and exec, manifest editing, Secret inspection, and dock behavior
- refreshed the Go, Kubernetes, SQLite, networking, React, icon, and frontend build dependencies

## Added

- Kubernetes Secret-backed authentication configuration:
  - startup import from `beaverdeck-config` / `config.yaml` by default
  - Secret creation after successful first-time initialization
  - admin-only YAML export and import
  - partial valid snapshots are normalized with missing optional sections
  - startup fails with a stage-specific error if an existing Secret cannot be imported
- `hash-password` utility command for generating `bdk1$...` local password hashes
- Helm-managed ConfigMap for globally suppressed Insight checks
- explicit Secret data reveal with decoded values for users with Secret manage permission
- container selection for pod logs and exec in multi-container pods
- reload controls for manifest viewing and editing
- new Insight checks for:
  - node underutilization based on requested CPU and memory
  - workload resource requests and limits
  - GPU capacity and metrics availability
  - missing NetworkPolicy coverage
  - suspicious literal environment variables containing names such as `PASSWORD`, `TOKEN`, or `SECRET`

## Changed

- authentication configuration is no longer stored in SQLite
- first-time initialization now asks for the admin username and password in the UI and no longer uses a bootstrap token
- only the admin role is created by default; `mode: admin` grants all BeaverDeck permissions without an explicit permission map
- non-admin permissions use compact YAML levels such as `workloads: edit`; omitted permissions mean no access
- login sessions are signed in memory and are not persisted server-side
- suppressed Insight checks apply globally to all users and are stored only in the ConfigMap
- pod capacity checks moved to Workload Insights and node capacity checks moved to Node Insights; the separate Capacity Insights section was removed
- update checks now send only the current application version
- editing an existing manifest requires the matching resource edit permission; arbitrary Apply YAML remains a separate permission
- dependency baselines now include Go `1.26.4`, Kubernetes libraries `0.36.2`, `golang.org/x/net` `0.55.0`, modernc SQLite `1.53.0`, React `19.2.7`, lucide-react `1.22.0`, and Vite `8.1.0`

## Removed

- Audit UI, API, and local audit storage
- persisted server-side login sessions and external-user cache records
- bootstrap token state
- default viewer role
- authentication configuration tables in local SQLite

## Fixed

- fixed configuration import so Google OAuth and generic OIDC/Entra configuration and mappings are replaced by the imported snapshot
- fixed auth provider metadata remaining stale after an admin configuration import
- fixed pod log follow-tail state being reset during refresh
- fixed logs and exec failing when a pod contains multiple containers
- fixed multi-container exec terminal resizing and dock attachment
- fixed manifest editing so removed lines are not retained, and added a full reload path that discards local edits
- fixed manifest Edit requiring the unrelated Apply YAML permission
- fixed lower-dock resize behavior when decoded Secret data is visible
- fixed Local Users actions overflowing the table or using inconsistent alignment
- fixed unnecessary data loading when opening individual Insight sections
- fixed navigation density, collapsed-section defaults, and section hover behavior

## Security

- updated the build toolchain to Go `1.26.4`
- updated `golang.org/x/net` to `0.55.0` for current HTML, IDNA, and networking security fixes
- updated Kubernetes clients and SQLite dependencies
- configuration import uses strict YAML decoding, bounded input, normalization, and validation
- local password exports contain password hashes only; raw passwords are never exported
- Secret decoded values require explicit Secret manage permission
- Security Insights detect sensitive literal environment-variable names using contains-style matching

## Deployment Notes

- app version: `1.5.0`
- Helm chart version: `2.2.0`
- breaking auth storage change: authentication configuration from BeaverDeck `1.4.1` and earlier SQLite databases is not migrated automatically
- before upgrading an existing installation, prepare a valid auth configuration Secret or plan to initialize the admin account and reconfigure roles and identity providers after the upgrade
- startup removes legacy auth tables from the local SQLite database; do not start `1.5.0` against the only copy of old auth data until the new Secret configuration is ready
- the default auth Secret is `beaverdeck-config` with key `config.yaml` in the release namespace
- the chart creates an empty suppressed Insights ConfigMap; all checks are enabled until globally suppressed
- pod restarts invalidate active login sessions because sessions are intentionally not persisted
- no Helm value was removed, but the chart adds the `suppressedInsights` configuration block and additional RBAC access for ResourceQuotas
