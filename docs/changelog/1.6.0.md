# BeaverDeck 1.6.0

`BeaverDeck 1.6.0` is a Kubernetes application visibility, restart diagnostics, custom-resource, and security-hardening release.

## Highlights

- browse installed CRDs and their custom resources through a compact `CRDs → API group → kind` navigation tree
- inspect Helm release status, revision history, computed values, user-applied values, and rendered resources
- inspect Argo CD Application status, deployment history, source configuration, and current created-resource inventory
- capture a bounded Restart Diagnostics snapshot when a pod restarts or is evicted, without requiring Prometheus or a log backend
- strengthen namespace authorization, auth-config persistence, request limits, dependencies, and default Helm runtime security

## Added

### CRDs and custom resources

- added dynamic discovery for every installed CRD and its served storage version
- grouped CRD navigation by API group and exposed clickable groups plus individual kinds
- added namespaced and cluster-scoped custom-resource tables with Manifest, Edit, and Delete actions
- added sample Widget CRD and Widget resource templates to Apply YAML
- added server-side namespace enforcement for custom-resource inventory and actions

### Applications

- added the Applications section with expandable Helm Releases and Argo CD Applications providers
- added Helm 3 release discovery from Kubernetes Secrets and ConfigMaps, current status, and revision history
- added Applications Manage actions for Helm computed values, user-applied values, and rendered resources in the YAML dock
- added Argo CD Application sync and health status, source and destination summaries, and deployment history
- added Applications Manage actions for Argo CD historical source configuration and the current revision's created-resource inventory
- added section-wide `applications` permissions: None, View, and Manage

### Restart Diagnostics

- added bounded in-memory pod-container and node CPU/memory history with Metrics Server and kubelet fallback
- added restart and eviction detection through a Kubernetes pod informer
- added one latest `beaverdeck-restart-<pod-name>` Secret per pod, including all containers' bounded previous logs
- added T-3m, T-1m, T-30s, and T-10s pre-incident metric points with sampling-jitter tolerance
- added node usage, allocatable and capacity totals, other pods on the node, and relevant pod/node events
- added PVC/PV metadata and related Kubernetes events to incident snapshots
- added automatic consolidation and cleanup for legacy, missing-pod, and UID-replaced snapshot Secrets

## Changed

- pod status now reflects actionable container states such as `OOMKilled` and `CrashLoopBackOff` instead of reporting only the broad Pod phase
- Applications permissions default to None for new and existing roles that do not explicitly contain the field
- auth configuration mutations are serialized with Kubernetes Secret persistence and roll back runtime state and session versions if the save fails
- aggregate namespace requests use at most eight Kubernetes API workers
- API request bodies are capped at 4 MiB; interactive logs are capped at 10,000 lines and 16 MiB
- Helm release payloads are capped at 32 MiB after decompression and isolated corrupt records no longer hide valid releases
- the default chart pod uses `RuntimeDefault` seccomp and a read-only root filesystem with writable `/data` and `/tmp`
- an empty `persistence.storageClass` now selects the cluster default StorageClass for new or reset-value installations
- Kubernetes Go libraries were updated to `0.36.3`, SQLite to `1.56.0`, PostCSS to `8.5.26`, and nanoid to `3.3.18`
- Cluster Health reuses the metrics-enabled Pods response instead of requesting the same pod inventory twice

## Fixed

- fixed Apply YAML accepting an explicit `metadata.namespace` outside the selected, role-authorized namespace
- fixed auth runtime state diverging from the durable configuration Secret after failed or reordered saves
- fixed duplicate Restart Diagnostics controls and Secrets for multi-container pods
- fixed the restart indicator shifting when the restart count became two digits
- fixed workload warning indicators opening logs instead of relevant Kubernetes events
- fixed Restart Diagnostics losing older pre-incident metric points because of exact timestamp matching
- fixed the Restart Diagnostics header and close action scrolling out of view
- fixed stale restart snapshot Secrets accumulating after pods disappeared or were replaced
- fixed nested CRD, Helm, and Argo CD navigation selection and indentation inconsistencies

## Security

- updated the Go toolchain and container build image from Go `1.26.5` to `1.27rc3` for the reported standard-library fixes
- validated the release with source `govulncheck`, which reports no known vulnerabilities
- closed the Apply YAML cross-namespace authorization bypass before objects reach the Kubernetes client
- updated vulnerable frontend build dependencies; full `npm audit` reports no vulnerabilities
- bounded request, log-stream, namespace fan-out, and compressed Helm release resource consumption
- added explicit `create` access for `policy/pods/eviction` and retained arbitrary custom-resource operations through the chart's wildcard rule
- removed the unused `logMutation` stub and the nonexistent Audit endpoint from the OpenAPI document

## Deployment and Upgrade Notes

- app version: `1.6.0`
- Helm chart version: `2.2.5`
- the default image tag is now `1.6.0`
- no Helm value was removed; the new `restartDiagnostics` block is enabled by default
- Restart Diagnostics Secrets can contain application logs. Review Kubernetes Secret access, retention expectations, and namespace policy before enabling the feature in sensitive workloads; set `restartDiagnostics.enabled=false` to disable it
- roles created before this release do not receive Applications access automatically. Grant `applications: view` or `applications: edit` explicitly
- the chart ServiceAccount now has wildcard get/list/create/update/patch/delete access across API groups and resources so BeaverDeck can operate on arbitrary CRDs. Review or replace the generated ClusterRole when this scope does not match the cluster trust model
- the chart explicitly grants pod eviction for Evict and Drain workflows
- `persistence.storageClass` defaults to empty. New installs use the cluster default StorageClass; set the value explicitly when a particular class is required
- Helm SQL storage is not supported, and an absent Argo CD Application CRD produces an empty Applications inventory
- the build baseline is Go `1.27rc3`; replace it with the final Go 1.27 release only after equivalent compatibility and security validation
