# BeaverDeck 1.6.1

`BeaverDeck 1.6.1` is a patch release focused on a new role-scoped operational Dashboard, clearer Insights presentation, safer live logs and diagnostics, broader bulk operations, and independent OpenID Connect and Azure Entra ID configuration.

## Added

- added Dashboard as a standalone top-level navigation item and the default page after every login
- added a visible-health score, capacity and readiness bars, pod-status distribution, top pod consumers, warning events, resource inventory, and Insights summaries
- made Dashboard universally reachable without introducing a new role permission while loading each panel only for resources and namespaces the current role may view
- limited Dashboard Insights summaries to categories whose underlying source resources are also visible to the current role

## Changed

- made Dashboard data sources load independently so completed charts appear without waiting for the slowest request
- combined all role-allowed Dashboard Insights categories into one backend scan instead of repeating shared Pod, Node, and Event queries per category
- reused Nodes already loaded by a combined Insights scan when collecting storage volume stats
- made Dashboard PVC/PV inventory skip node volume-stat collection; full PVC/PV pages keep usage metrics enabled by default
- limited Dashboard events to the 30 most recent warnings per selected namespace with a server-side Kubernetes `type=Warning` selector, and aligned paired dashboard panels to equal heights
- grouped Insight results by stable check type so repeated findings such as root-user workloads appear in one card with a compact list of affected resources
- kept resource navigation, log access, suppression, severity, passing, and suppressed counts available for each grouped Insight result
- replaced the browser-native Apply YAML template selector with a BeaverDeck-styled, keyboard-dismissable popover that follows the active theme and viewport
- added consistent multi-select and RBAC-aware bulk Delete actions to resource tables that already support deletion; Workloads also support bulk restart for Deployment-only selections
- added a Reconnect control for interrupted Pod Exec sessions without discarding the existing terminal tab or output
- changed Pod and Workload Follow to a live authenticated stream instead of repeatedly downloading complete log snapshots
- bounded streamed log tabs to 5000 lines or 4 MiB and batched high-volume UI updates

## Fixed

- fixed generic OpenID Connect and Azure Entra ID overwriting each other's provider configuration
- separated OIDC and Entra group mappings, admin endpoints, OAuth state, role resolution, external-session source, disable actions, and login buttons
- added automatic migration of legacy Entra configuration and mappings from the old shared `oidc` snapshot section to the new `entra` section
- kept a deliberately generic OIDC provider on a Microsoft issuer in `oidc` when the imported snapshot already contains an explicit `entra` section
- preserved the historical `/api/auth/oidc/callback` redirect URI so existing Entra application registrations do not need to change
- fixed the Dashboard health score omitting an accessible Insights source when every check was passing
- fixed recent Kubernetes Events with `eventTime` being sorted behind legacy `lastTimestamp` events before result limiting
- fixed Restart Diagnostics expanding beyond its intended width when logs contain long lines
- fixed delayed Metrics API values being discarded when their Kubernetes sample timestamp was before the incident but BeaverDeck received them just after it
- fixed Follow stopping on a log line larger than the scanner buffer; oversized lines are now visibly truncated after 1 MiB while later lines continue streaming
- fixed logs emitted while Follow autoscroll is paused disappearing after Follow is enabled again

## Deployment and Upgrade Notes

- app version: `1.6.1`
- Helm chart version: `2.2.6`
- the default image tag is `1.6.1`
- no Helm value or environment variable was removed
- no database migration is required
- auth configuration snapshots now export separate `oidc` and `entra` sections; legacy Entra settings in `oidc` are migrated and persisted automatically after a successful startup import
- both generic OIDC and Azure Entra ID can be configured and enabled simultaneously
