# BeaverDeck 1.6.2

`BeaverDeck 1.6.2` is a patch release that closes a session-lifetime security gap: logout, tab close, and page refresh now genuinely invalidate the session token on the server instead of only clearing client-side state.

## Security

- fixed session tokens remaining valid after logout, a page refresh, or a closed tab; sessions are now tracked server-side and revoked immediately on any of these events
- added a background sweeper that clears revoked and expired session records so server-side session state does not grow unbounded

## Fixed

- fixed `POST /api/auth/logout` being a no-op that only cleared client-side React state without invalidating the token on the server
- fixed a copied or leaked session token (for example from the browser DevTools Network tab) continuing to work against any API endpoint after the user logged out, refreshed the page, or closed the tab

## Changed

- added a `pagehide` handler that notifies the server with a `keepalive` request when a tab is closed, refreshed, or navigated away from, so the session ends synchronously with leaving the page

## Deployment and Upgrade Notes

- app version: `1.6.2`
- Helm chart version: `2.2.7`
- the default image tag is `1.6.2`
- no Helm value or environment variable was removed
- no database migration is required
- server-side session state is in-process memory only, like the existing token-signing key; a pod restart clears all active sessions, same as before
