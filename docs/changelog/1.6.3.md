# BeaverDeck 1.6.3

`BeaverDeck 1.6.3` is a patch release that makes application version reporting deterministic, improves Kubernetes Event triage, and restores log access for pods blocked in init containers.

## Security

- updated the transitive frontend build dependency `source-map-js` from `1.2.1` to `1.2.2` to resolve its indexed source-map denial-of-service advisory

## Added

- added a search field to Events that filters timestamp, namespace, type, reason, object, message, and count
- added Event severity colors consistent with Pod logs: Warning is yellow, Error is red, and other events use the normal log text color

## Fixed

- fixed Pod logs omitting init containers from the container selector
- fixed pods blocked or crashing during initialization defaulting log requests to an application container that has not started; BeaverDeck now selects the active or failing init container while preserving regular-container selection for Exec
- fixed runtime application version reporting depending on the deployed image tag being copied into `APP_VERSION`

## Changed

- compiled the application version into the Go binary as the single runtime source used by the login metadata, `/api/me`, and update-check payload
- removed the `APP_VERSION` environment variable from the Helm Deployment
- removed runtime support for `UPDATE_CHECK_URL`; update checks now use the official `https://beaverdeck.io/update-check` endpoint
- retained Helm `appVersion` and `image.tag` as packaging and image-selection metadata only; they no longer configure the running binary's reported version

## Deployment and Upgrade Notes

- app version: `1.6.3`
- Helm chart version: `2.2.8`
- the default image tag is `1.6.3`
- `APP_VERSION` and `UPDATE_CHECK_URL` are no longer runtime configuration inputs
- no database migration is required
