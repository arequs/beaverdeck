# BeaverDeck 1.7.0

`BeaverDeck 1.7.0` introduces the first direct browser routes while preserving the existing in-cluster
authorization model and authentication providers.

## Navigation

- added direct routes for Login, Dashboard, and Events
- retained `/_workspace` as the transition route for screens that have not yet received dedicated URLs
- added browser Back/Forward behavior between routed pages
- retained a validated destination after refresh, logout, or session expiry and restored it only after a fresh
  successful sign-in
- redirected an already-authenticated `/login` visit to Dashboard

## Events And Permissions

- added URL-backed namespace and search filters for Events
- checked explicit namespace filters against the signed-in user's current permissions before loading Events
- prevented an older Events response from replacing data for a newer route or namespace selection
- retained backend RBAC as the authoritative authorization boundary

## Base Path And Security

- added runtime SPA base-path injection for root and prefixed deployments
- made configured `BASE_PATH` authoritative for authentication redirects
- rejected ambiguous, traversal, encoded, backslash, and authority-like forwarded prefixes
- limited SPA fallback to GET and HEAD navigation requests
- rejected return destinations containing common credential query parameters
- kept Bearer credentials in React memory and preserved existing logout, expiry, restart, password, role, OIDC,
  Entra ID, and Google OAuth behavior

## Deployment And Upgrade Notes

- app version: `1.7.0`
- Helm chart version: `2.2.13`
- default image tag: `1.7.0`
- no database migration is required
- no Helm values or authentication-provider configuration changes are required
- existing non-root installations should keep `ingress.path` aligned with the externally visible application path
